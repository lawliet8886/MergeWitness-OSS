# MergeWitness

**Replay an interaction. Check what a repair keeps.**

MergeWitness is an independent MIT-licensed software initiative for technical leads of small Node teams. It compares a caller-authored sequence of operations across Git revisions and checks a candidate repair against frozen, explicitly declared requirements from both changes.

## The problem we are testing

Changes can pass their ordinary tests separately and together, while a particular operation sequence exposes a stateful interaction. A repair may remove that symptom by removing functionality the team still needs. Reviewers need an inspectable account of the sequence, observations and retained checks.

## What exists

The local 0.3.0 package provides a CLI, a four-operation stdio MCP interface, version 2 JSON evidence and an offline HTML reader. Its accepted tarball passed two installed Windows demonstrations; the complete native Linux suite passed 88 tests. The owner-private Site completed the recorded desktop/mobile review. These are internal technical checks, not customer adoption or universal repair guarantees.

The reproducible tenant-pricing/cache example is synthetic. Its supplied repair is identified as supplied. Public incident replays are known cases, not a blind benchmark. Related work includes QuietClash and mumei; originality and superiority are not established.

## First customer hypothesis and offer

A technical lead with a recent, repeatable stateful interaction in a trusted Node repository. The first integration pilot is free and limited to one repository, one case and up to two technical sessions. The team retains its source and merge decision. Only reviewed, trusted code is eligible; subprocesses and worktrees are not hardened sandboxes.

The commercial hypothesis is an open MIT core with paid integration and maintenance help if repeated demand appears. Pricing, willingness to pay and recurring demand have not been validated. No hosted execution service is offered.

## AI-assisted review hypothesis

An optional model can suggest a candidate while MergeWitness retains the declared checks and execution evidence. One proposal obtained through Claude web chat and forwarded by the user passed local verification and a fresh replay in the synthetic example. The user supplied the response; provider UI/model identity were not independently captured. The founder has no Claude Pro subscription; Claude Code is not included in Claude Free. No new subscription, API key or billing route has been configured. A later Claude Code/MCP workflow is a separate validation gate.

## Evidence we need next

Five outside developers will test comprehension and reproduction. Internal learning targets are three unaided reproductions in roughly ten minutes, one consented real external case and two concrete returns after 7–14 days. Assisted attempts, failures and missing follow-ups will be reported. Public distribution and invitations require separate authorization.
