Two changes can pass their tests, then fail when they meet. The problem may be hidden in the order of operations, even after a clean Git merge.

Merge Witness replays that sequence across Git revisions, compares the observations, and checks what a candidate repair keeps. Its open source MIT core runs locally in a trusted Node repository. You can inspect the recorded evidence in an offline report.

In this synthetic example, one change adds prices for each tenant. Another adds a cache. Alpha has a price of ninety. Beta should receive the global price of one hundred. But the combined cache uses only the product key. After Alpha, Beta receives ninety. The ordinary tests pass. The frozen sequence exposes the interaction.

Before asking for a repair, we freeze the sequence and declare what each change must retain. For this demonstration, the user obtained a Claude proposal through web chat and forwarded it. We reviewed the code, then a local controller applied it unchanged. The new key combines tenant and product.
